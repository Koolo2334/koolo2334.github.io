## 作品紹介

Siv3D（C++）で制作したビジュアルノベルエンジン「からから」です。シナリオは独自のスクリプト言語（`.karamp2`）で書き、キャラクターの立ち絵・背景・スクリプトの一覧は TOML ファイルで管理します。画面上のキャラクターをクリックすると、そのキャラクターの会話が始まる、探索型のノベルゲームを想定した作りです。

エンジン本体に加えて、スクリプトを書きやすくするための VSCode 拡張機能と、アセット登録支援ツールも制作しました。

## 課題と解決

<Case n="01" title="場面ごとに、キャラクターがそれぞれの会話を持つ構成を書きたい">
  <Fragment slot="problem">
    探索型のノベルゲームでは、話が上から順に進むのではなく、プレイヤーがどのキャラクターをクリックするかで会話が変わります。一般的な「上から順に実行する」スクリプトでは、こうした構成を書きにくくなります。
  </Fragment>

  スクリプトを「セクション（場面）→ キャラクター → ラベル」の3階層で書く言語を設計しました。セクションには背景を、キャラクターには最初の立ち絵を指定します。ラベルはキャラクターごとの会話で、`:start` はクリックされたとき、`:auto` は場面が始まったときに実行されます。別の場面のキャラクター定義を `<<名前 : セクション>>` で流用することもできます。

  ```text
  // セクション「start」、背景は「train」
  [[start@train]]
  // キャラクターと最初の立ち絵
  <<Kani@room.window.sit.angry>>

  // Kani をクリックしたときの会話
  :start
  $好感度 = 10
  テストを開始します。\
  // 立ち絵を差分で変更
  @normal
  // 別のキャラクターが割り込んで話す
  &Kei@window.stand.normal
  割り込みテストです。
  // 別ファイルのセクションへ移動
  -> chapter1:section_event
  ```

  パーサはスクリプトを1行ずつ読み、場面ごと・キャラクターごとのコマンド列に変換します。複数行のセリフは1つのテキストにまとめ、キャラクターやラベルが切り替わる前に必ず確定させるようにしました。

  <Flow
    cols={[
      { label: '.karamp2', items: ['[[セクション@背景]]', '<<キャラ@立ち絵>>', ':ラベル'] },
      { label: 'ScriptParser', items: ['1行ずつ解析', '複数行のセリフを結合', '参照コピーを解決'] },
      { label: 'データ', items: [{ text: 'セクション → キャラ → ラベル', sub: 'ラベルごとのコマンド列', hot: true }] },
    ]}
    caption="ScriptParser.cpp、ScriptData.hpp"
  />

  <Fragment slot="result">
    「この場面で、このキャラクターに話しかけたら」という単位でシナリオを書けるようになりました。
  </Fragment>
</Case>

<Case n="02" title="立ち絵の差分が多く、毎回すべてを指定するのは手間がかかる">
  <Fragment slot="problem">
    立ち絵は「場所・位置・姿勢・表情」の組み合わせで増えていきます。表情を変えるだけでも、すべての要素を毎回書く必要があると、スクリプトが長くなり、書き間違いも増えます。
  </Fragment>

  立ち絵の名前を `room.window.sit.angry` のような階層にしました。TOML の入れ子のテーブルを再帰的にたどり、階層を `.` でつないだ名前で登録します。スクリプトで `@angry` のように後ろの階層だけを書くと、今の立ち絵の前の階層を残して差し替えます。立ち絵ごとに、クリック判定の範囲・テキストボックスの位置・描画順も持たせています。

  <Graph
    cols={[
      { label: '今の立ち絵', items: ['room.window.sit.normal'] },
      { label: 'スクリプト', items: ['@angry', '@stand.smile'] },
      { label: '新しい立ち絵', items: [{ text: 'room.window.sit.angry', hot: true }, { text: 'room.window.stand.smile', hot: true }] },
    ]}
    edges={[[[0, 0], [0, 1]], [[0, 0], [1, 1]]]}
    caption="VisualNovelEngine.cpp ResolvePosePath()、AssetLoader.hpp"
  />

  <Fragment slot="result">
    表情や姿勢の変化を短く書けるようになり、立ち絵が増えてもスクリプトが長くならない仕組みになりました。
  </Fragment>
</Case>

<Case n="03" title="分岐やフラグを、実行部を複雑にせずに扱いたい">
  <Fragment slot="problem">
    選択肢による分岐、フラグの計算、条件分岐をそれぞれ実行部で処理すると、コマンドの種類が増え、実行部の状態管理が複雑になります。
  </Fragment>

  選択肢のブロック（`#q` 〜 `#endq`）は、パースの段階で自動生成したラベルとジャンプ命令に展開します。実行部は「選択肢を表示して、選ばれたラベルへ飛ぶ」ことだけを扱えば済みます。

  フラグには日本語の変数名を使え、`$合計 = ($好感度 + $ボーナス) * 2` のような式を書けます。式は再帰下降パーサで評価し、四則演算・括弧・単項マイナスと比較演算子に対応しています。`#if` / `#else` / `#endif` は入れ子の深さを数えながら読み飛ばします。

  <Flow
    cols={[
      { label: 'スクリプト', items: ['#q 質問文', '#y はいの処理', '#n いいえの処理', '#endq'] },
      { label: 'パース時に展開', items: ['分岐：__q1_y / __q1_n', 'ジャンプ：__q1_end', 'ラベル __q1_y / __q1_n / __q1_end'] },
      { label: '実行時', items: [{ text: '分岐とジャンプだけを処理', hot: true }] },
    ]}
    caption="ScriptParser.cpp（#q の展開）、ExpressionParser.cpp"
  />

  <Fragment slot="result">
    実行部のコマンドを増やさずに、選択肢・フラグ・条件分岐を組み合わせたシナリオを書けるようになりました。
  </Fragment>
</Case>

<Case n="04" title="画面より広い背景を見渡しながら、キャラクターをクリックさせたい">
  <Fragment slot="problem">
    背景を画面より大きくし、マウスの位置に合わせて視点を動かす演出を入れると、画面上の座標とキャラクターの位置がずれ、クリックの判定が合わなくなります。
  </Fragment>

  背景ごとに、カメラが動ける範囲（`viewRect`）を TOML で指定します。カメラはマウスの位置をサイン関数で補間した位置へ動かし、画面の端ほどゆっくり止まるようにしました。クリックの判定は、マウスの座標にカメラの位置を足した「ワールド座標」で行います。キャラクターが重なっているときは描画順で手前のキャラクターを優先し、選択肢のボタンもワールド座標で判定する独自のボタンにしました。

  <Flow
    cols={[
      { label: '入力', items: ['マウスの画面座標'] },
      { label: 'カメラ', items: ['サイン関数で補間', 'viewRect の範囲内に制限'] },
      { label: '判定', items: [{ text: 'ワールド座標で判定', sub: '描画順で手前を優先', hot: true }] },
    ]}
    caption="VisualNovelEngine.cpp updateCamera()、update()"
  />

  <Fragment slot="result">
    奥行きを感じる視点の動きと、ずれのないクリック操作を両立できました。
  </Fragment>
</Case>

<Case n="05" title="独自スクリプトでは、入力ミスに気づきにくい">
  <Fragment slot="problem">
    独自のスクリプト言語には入力補完がなく、存在しないラベルやキャラクターの立ち絵を指定しても、実行するまで気づけません。
  </Fragment>

  TypeScript で VSCode 拡張機能を制作しました。シンタックスハイライトに加えて、エンジンと同じ TOML を読み込み、カーソル位置の文脈に合わせて補完します。`[[ ]]` の中では背景、`<< >>` の中ではキャラクターと立ち絵、`>>` の後ではラベル、`->` の後ではスクリプトとセクションを候補に出します。

  立ち絵の差分は、カーソルより上のスクリプトをたどって今の立ち絵を計算し、エンジンと同じ規則で有効になる差分だけを候補に表示します。通常のテキスト入力中は、エディタ標準の単語補完が出ないようにしました。

  <Flow
    cols={[

      { label: 'VSCode 拡張', items: ['カーソル位置の文脈を判定', '今の立ち絵を計算'] },
      { label: '補完', items: [{ text: '有効な候補だけを表示', hot: true }] },
    ]}
    caption="vnkscript/src/extension.ts"
  />

  <Fragment slot="result">
    書いている途中で、使える立ち絵やラベルが分かるようになり、実行してから入力ミスに気づく手戻りを減らせました。
  </Fragment>
</Case>
